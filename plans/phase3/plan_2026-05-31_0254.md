# Plan: async/await as BEAM processes (Phase 3 step 1)

**Date:** 2026-05-31 02:54 (local)
**Paired discussion:** [discussion_2026-05-31_0254.md](discussion_2026-05-31_0254.md)
**Status:** ready to implement
**Owner:** open

## What this delivers

TypeScript `async`/`await` compiling to BEAM processes. Each async
function call spawns a lightweight BEAM process; `await` collects the
result via message passing. True parallelism with familiar TS syntax.

```typescript
async function double(x: number): Promise<number> {
  return x * 2
}

const result = await double(21)
console.log(result)  // 42
```

## Scope

**In scope:**

- `async function` declarations (top-level module functions)
- `await` expressions as RHS of `let`/`const` or as terminal expr
- Promise representation as `{Ref}` tuple
- Spawned process sends `{Ref, Result}` to caller on completion
- `await` emits `receive` matching on the Ref
- Compile error on unawaited async function calls (strict mode)
- Variable capture in async function bodies (same as arrow capture)

**Out of scope:**

- `await` mid-body inside async functions (needs async CPS — step 2)
- `Promise.all`, `Promise.race` (step 3)
- Explicit `spawn`/`send`/`receive` API (step 4)
- Error propagation across processes (step 5)
- `async` arrow functions (later; start with declarations)
- Timeouts on await
- Nested async (async calling async internally)

## Architecture

### Promise representation

A promise is a one-element tuple `{Ref}` where Ref is a unique BEAM
reference created by `make_ref()`. The spawned process captures both
the caller PID (`self()` at call time) and the Ref.

### Async function emission

An `async function foo(x)` emits as a regular Core Erlang function
that:

1. Captures the caller PID via `self()`
2. Creates a unique Ref via `make_ref()`
3. Spawns a process running the function body
4. The spawned process sends `{Ref, Result}` to the caller
5. Returns `{Ref}` (the promise)

```erlang
'foo'/1 = fun (_x) ->
  let <_caller> = call 'erlang':'self'()
  in let <_ref> = call 'erlang':'make_ref'()
  in do call 'erlang':'spawn'(fun () ->
    let <_result> = << body using _x >>
    in call 'erlang':'!'(_caller, {_ref, _result})
  end)
  {_ref}
```

### Await emission

`await expr` evaluates the expression (which must return a `{Ref}`
promise tuple), extracts the Ref, and does a receive:

```erlang
let <_promise> = << emit expr >>
in let <_ref> = call 'erlang':'element'(1, _promise)
in receive
  {_awaitRef, _val} when call 'erlang':'=:='(_awaitRef, _ref) ->
    _val
after 'infinity' -> 'error'
```

The `after 'infinity'` clause is required by Core Erlang receive
syntax but never fires (infinite timeout = block forever).

### Unawaited async call rejection

When `emitCall` detects a call to a function marked `async` and the
call is NOT wrapped in an `await` expression, emit a CompileError:

```
async function 'foo' must be awaited — use: await foo(...)
```

Detection: in `emitExpression`, when processing a `CallExpression`
whose target resolves to an async function and the parent node is NOT
an `AwaitExpression`, throw.

### No changes to build.ts needed

Because `await` blocks the calling process (main) until the result
arrives, `main/0` doesn't return until all awaited work is complete.
The existing `erl -eval 'module:main(), halt().'` invocation works
unchanged.

## Implementation steps

### Step 0: sandbox-first — verify Core Erlang receive

Hand-write a Core Erlang module in `local_sandbox/` that:
- Spawns a process
- The spawned process sends `{Ref, Value}` to the parent
- The parent does `receive` matching on the Ref
- Prints the received value

Feed through `erlc +from_core` and `erl -eval`. Confirm:
- Receive syntax with guard-based ref matching works
- Variable capture in spawned fun works
- `make_ref()` + `self()` + `!` (send) work at Core Erlang level

This MUST succeed before writing any emitter code.

### Step 1: track async functions in the emitter

Add a `Set<string>` field `asyncFunctions` to the Emitter class.
During the initial statement scan (where we collect
`moduleFunctions` and `interfaces`), also detect async function
declarations and record them.

Detection: `node.modifiers?.some(m => m.kind === ts.SyntaxKind.AsyncKeyword)`

### Step 2: emit async function declarations

When emitting a function declaration that's in `asyncFunctions`,
wrap the body in the spawn+send protocol:

1. `let _caller = self()` 
2. `let _ref = make_ref()`
3. `spawn(fun () -> let _result = <body> in _caller ! {_ref, _result})`
4. Return `{_ref}`

The function's arity stays the same (params don't change).

### Step 3: emit await expressions

Add a branch in `emitExpression` for `ts.isAwaitExpression(expr)`:

1. Emit the operand (the async call)
2. Extract the ref: `element(1, promise)`
3. Emit receive with ref-matching guard

### Step 4: reject unawaited async calls

In `emitCall`, after determining the target is in `asyncFunctions`,
check if the call's parent is an AwaitExpression. If not, throw
CompileError with guidance.

Implementation detail: `expr.parent` gives us the parent node. If
parent is `ts.isAwaitExpression`, it's fine. If parent is anything
else (variable initializer, expression statement, argument), reject.

Per the AGENTS.md "full interaction matrix" rule, async/await is
combined with every existing feature it plausibly touches within step

| Fixture | Combo axis |

| Fixture | Combo axis |
|---------|-----------|

| Fixture | Combo axis |
|---------|-----------|
| `combo_async_nested_await` | `await f(await g(x))` |

**Axes skipped (with reason):**

- `Promise.all` / arrays-of-promises — out of step 1 scope (step 3).
- await captured inside an *arrow body* — needs async arrows (deferred).
- async returning `Set` — same path as `Map` (both BEAM maps);

- async + recursion — a recursive async that awaits itself needs
  mid-body await (step 2); single-return recursion isn't meaningfully
  async.

## Risks

1. **Core Erlang receive syntax** — might have gotchas we haven't
   hit before (guard-based matching, variable scoping in receive
   patterns). Mitigated by sandbox-first (step 0).

2. **Variable capture in spawned funs** — async function params must
   be accessible inside the spawned closure. Should work the same as
   arrow function capture, but verify in sandbox.

3. **Fresh variable names** — the emitter generates `_caller`,
   `_ref`, `_result` etc. These must not collide with user variable
   names. Use a prefix like `_tsbeam_` or a counter-based scheme.

4. **Parent-node detection for unawaited rejection** — TypeScript
   AST parent references may need `ts.forEachChild` or explicit
   parent tracking. Verify that `expr.parent` is populated after
   parsing.

## Implementation notes

Went through cleanly in one pass. Final state: 3 new positive fixtures
(async_basic, async_multiple_awaits, async_string), 1 new negative
fixture (async_unawaited_rejected). 56 total passing (up from 52).

1. **Core Erlang `receive` syntax works at the simple level.** Despite
   the Erlang compiler generating complex primop-based receive loops
   internally (`recv_peek_message`, `recv_next`, etc.), `erlc +from_core`
   still accepts the high-level `receive ... after ... ` form as input.
   It handles the lowering to primops internally.

2. **`<<"...">>` binary shorthand is NOT valid Core Erlang.** This was
   the cause of confusing "illegal expression" errors during sandbox
   exploration. The `io:format` call uses char-list strings (`"~p~n"`)
   which ARE valid. Our existing `emitStringLiteralAsBinary` (canonical
   segment syntax `#{...}#`) is correct.

3. **Guard-based ref matching in receive works.** The pattern
   `<{_AwaitRef, _Val}> when call 'erlang':'=:='(_AwaitRef, _Ref)` is
   the right way to match on a previously-bound ref in Core Erlang
   receive clauses. Pattern variables in receive are always fresh.

4. **Nested `let` is valid Core Erlang.** `let <X> = let <Y> = E in F
   in G` parses and compiles. This means `emitAwaitExpression` can
   return a multi-expression let chain and it works as the RHS of the
   variable binding from `const result = await fn()`.

5. **Variable capture in spawned funs works identically to arrow
   functions.** The spawned `fun ()` captures `_Caller`, `_Ref`, and
   all function parameters from the enclosing scope — same closure
   mechanism we already use for arrows.

6. **`insideAwait` flag for unawaited detection.** Used a simple boolean
   flag on the Emitter class rather than parent-node traversal. Set to
   true inside `emitAwaitExpression` before emitting the operand, reset
   after. `emitCall` checks the flag when the target is an async
   function.

7. **Fresh variable naming with `__base_N` scheme.** Counter-based
   (`__caller_0`, `__ref_1`, etc.) avoids all collision with user
   variables (which go through `tsIdentifierToCore` and get `_` prefix).

No deviations from scope. No changes needed to `build.ts` or the CLI.
The existing `halt()` invocation works because `await` blocks main
until results arrive.

### Combination matrix round (added per AGENTS.md interaction-matrix rule)

The first cut shipped only win-condition fixtures. Adding the full
combination matrix surfaced two issues:

8. **Nested await falsely rejected (`await f(await g(x))`).** The
   original unawaited-detection used a mutable `insideAwait` boolean.
   Because `emitCall` evaluates arguments *before* checking the async
   guard, the inner await reset the flag to false before the outer
   call's check ran — so the outer async call was wrongly rejected.
   Fixed by switching to parent-node detection:
   `ts.isAwaitExpression(expr.parent)`. This is order-independent and
   strictly more correct. The boolean field is gone.

9. **Async function returning an interface emitted a map, not a
   record (runtime crash).** An async fn returning `Promise<User>`
   gives its return expression the contextual type `User |
   Promise<User>` (TS lets you return either a value or a promise from
   an async body). `interfaceNameFor` only looked at the top-level
   type symbol, which for a union is undefined → fell back to map
   emission. But the *await result* correctly typed as `User`, so
   property access emitted record `element/2` against a map →
   `badarg`. Fixed by adding `interfaceNameOfType`, which scans union
   constituents for a known interface. Additive: non-union types keep
   the exact prior behavior. The sync case (`function f(): User`)
   already worked because its return type is a bare interface, not a
   union — this bug was async-specific.

10. **`%` (modulo) is unsupported** — hit while drafting a `.filter`
    predicate. Not an async bug; pre-existing emitter gap. Reworked the
    fixture predicate to `x > 2`. Noting here so a future agent adding
    arithmetic operators knows `PercentToken` is missing.

Final fixture count after the matrix round: 4 win-condition + 11 combo
= 15 new async fixtures. 67 total passing.
